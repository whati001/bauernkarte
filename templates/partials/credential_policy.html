{#- Live credential checklists: the rows under the email and password fields that light up as the value satisfies each rule. Macros rather than two hand-copied blocks, because the same list appears on the register form and on the account page's change-password form, and a rule that drifts between them is a rule the visitor can't trust. Nothing here evaluates anything — `static/credential-policy.js` reads `data-policy-for` to find the input and `data-rule` to pick the predicate, and toggles `.met` on each row. The rule *names* are the contract between this file, that one, and `PasswordRule` in `src/auth/password.rs`, which enforces the same rules server-side. Every row ships both state icons and both screen-reader labels, and CSS shows whichever matches `.met` — that way JS never has to author markup or hold a translated string. -#} {% macro row(rule, label_key) %}
