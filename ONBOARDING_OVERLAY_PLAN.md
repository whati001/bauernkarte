# First-Visit Onboarding Overlay

## Context
Add a polished, first-visit-only onboarding overlay to the existing Dioxus application. It must explain product search, store search, navbar/login, adding a store, and changing a store as five simple pages; users can skip it, and a browser-local value suppresses later display. The intended end state is a responsive bilingual guide whose five locale-matched page images are reproducibly captured from the running application by a new `service.py` command.

## Approach
1. **Generate the checked-in tutorial images from the real app.**
   - Extend `service.py`'s module command inventory/usage and PEP 723 dependencies with `playwright==1.55.0`; add constants for default fixture `Obstgarten Maier`, storage key `bk-onboarding-complete-v1`, viewport `1280×800`, and output root `public/static/onboarding`, plus `def do_screenshots(base_url, store_name):` and Click command `screenshots --base-url URL --store-name TEXT` whose wrapper is `def screenshots(base_url, store_name):`. `--store-name` defaults to `Obstgarten Maier` and shows that default in `--help`; strip surrounding whitespace and reject an empty result with `--store-name must not be empty`. Default the URL to `http://127.0.0.1:{APP_PORT}`; normalize one trailing slash, require an `http`/`https` URL, and probe `{base_url}/healthz` for status 200/body `ok` before opening a browser.
   - Require the app and an exact visible public result matching `store_name`; do not start services, fetch OSM seed data, or mutate the database. Use actionable Click errors containing exactly `run ./service.py up or pass --base-url` for missing health; for a missing default fixture, `store 'Obstgarten Maier' is missing or not public — run ./service.py stores --demo first`; for a missing custom name, `store '{store_name}' is missing or not public — seed it before running screenshots`; for a missing browser, `uvx --from playwright==1.55.0 playwright install chromium`; and for rejected credentials, `admin login failed; verify ADMIN_PASSWORD and restart the app`. Never install Chromium or OS packages implicitly.
   - Launch headless Playwright Chromium with viewport `1280×800`, scale 1, light color scheme, reduced motion, blocked service workers, `Europe/Vienna`, fixed geolocation `(47.1043, 15.7086)`, and fixed time `2026-10-24T10:00:00+02:00`. Before navigation, set `bk-onboarding-complete-v1` to `"true"` and inject capture-only CSS disabling animation, transitions, and carets. Set cookie `locale=de` or `locale=en`; never log `ADMIN_PASSWORD`.
   - For each locale, first open the search sidebar, fill `.toolbar-search input` with the exact `store_name`, require exactly one `.result-card` whose `.result-name` equals it (other fuzzy result cards may remain), read that card's first `.result-chip` product name by dropping the leading icon and space, and derive the runtime store ID by clicking the exact card and parsing `/store/{id}`. Fail as missing/invalid data if there is no unique exact-name card or first product; never assume a database sequence value. Then capture full viewport PNGs in the requested order after hydration, route anchors, `document.fonts.ready`, visible images, one `.leaflet-tile-loaded`, and two animation frames:
     1. `search-product.png`: fresh `/`, focus `.nav-search input`, enter the product name derived from the selected store, and leave its matching `[role=option]` list open.
     2. `search-store.png`: fresh `/`, click `#sidebar-open`, fill `.toolbar-search input` with the exact `store_name`, and wait for its unique exact-name card plus a `.map-pin-dot`.
     3. `navbar-login.png`: anonymous `/login`, waiting for `#login-email` and `#login-password`, so navbar/login/register affordances are visible together.
     4. `add-store.png`: log in through those two fields using `bauernkarte@rehka.dev` and `.env`'s `ADMIN_PASSWORD`, require navigation away from `/login` and visible `.nav-user`, then visit `/new-store` and wait for empty `#store-name`.
     5. `change-store.png`: while authenticated, visit the previously resolved `/store/{id}/edit`, wait for prefilled `#store-name` equal to `store_name`, and show the existing edit form/location.
   - Write the ten files to a temporary sibling tree first, verify each Playwright capture completed as a PNG, and only then replace `public/static/onboarding/{de,en}/{search-product,search-store,navbar-login,add-store,change-store}.png`. Close browser contexts in `finally` and convert Playwright/HTTP/selector/login failures into actionable `click.ClickException`s. No screenshot helper script or app-image Chromium dependency: no equivalent tooling exists, and keeping this in the requested CLI avoids a second command convention.

2. **Define the bilingual five-page contract and persistence disclosure.**
   - Add exact keys `onboarding-search-product-title`, `onboarding-search-product-body`, `onboarding-search-store-title`, `onboarding-search-store-body`, `onboarding-navbar-login-title`, `onboarding-navbar-login-body`, `onboarding-add-store-title`, `onboarding-add-store-body`, `onboarding-change-store-title`, `onboarding-change-store-body`, `onboarding-skip`, `onboarding-next`, and `onboarding-finish` to both `locales/de.ftl` and `locales/en.ftl`; preserve their enforced identical key sets. Use these exact page strings:
     - Product — DE title `Produkt suchen`, body `Gib oben ein Produkt ein oder wähle einen Vorschlag. Karte und Liste zeigen dir passende Geschäfte.`; EN title `Search for a product`, body `Type a product at the top or choose a suggestion. The map and list show matching stores.`
     - Store — DE title `Geschäft suchen`, body `Öffne die Seitenleiste und suche nach dem Namen eines Hofladens, Automaten oder Markts.`; EN title `Search for a store`, body `Open the sidebar and search for the name of a farm shop, vending machine, or market.`
     - Navbar/login — DE title `Navigation und Login`, body `In der oberen Leiste wechselst du die Sprache und meldest dich an. Mit einem Konto kannst du Geschäfte hinzufügen und ändern.`; EN title `Navigation and login`, body `Use the top bar to change language and log in. With an account, you can add and change stores.`
     - Add — DE title `Neues Geschäft hinzufügen`, body `Melde dich an, öffne dein Kontomenü und wähle „Neues Geschäft“. Trage die Daten ein und setze den Standort auf der Karte.`; EN title `Add a new store`, body `Log in, open your account menu, and choose “New Store”. Enter the details and set the location on the map.`
     - Change — DE title `Geschäft ändern`, body `Öffne ein Geschäft, scrolle zu den Aktionen und wähle „Bearbeiten“. Passe die Daten an und speichere.`; EN title `Change a store`, body `Open a store, scroll to its actions, and choose “Edit”. Update the details and save.`
   - Add controls `Überspringen`/`Skip`, `Weiter`/`Next`, and `Los geht's`/`Get started`; reuse existing `action-back` for Back. The visual and accessible step indicator is numeric (`1 / 5` … `5 / 5`), requiring no new interpolation API. Screenshots are decorative (`alt=""`) because the adjacent title/body contains the instructions.
   - In `src/components/datenschutz.rs` add a storage-list item for exact key `datenschutz-storage-onboarding`. Its DE text is `localStorage-Schlüssel bk-onboarding-complete-v1 für die einmalige Einführung: bis die Website-Daten gelöscht werden.` and EN text is `localStorage key bk-onboarding-complete-v1 for the one-time introduction: until site data is cleared.` In `datenschutz-retention-body`, change the relevant DE clause to `die Seitenleistenbreite und der Abschluss der Einführung bis zum Löschen der Website-Daten` and EN clause to `the sidebar width and introduction completion until site data is cleared`; leave the other retention periods intact.

3. **Render a responsive, explicit-dismiss onboarding dialog on first public-map use.**
   - Create `src/components/onboarding.rs` because no onboarding/tour component or semantically suitable app dialog wrapper exists; export it from `src/components/mod.rs`, and mount `Onboarding {}` as the last child of `div.app` in `src/components/shell.rs::MapShell`. This keeps one instance across every public map/search/login/store/form/legal route and intentionally excludes `AdminShell`.
   - Implement `pub fn Onboarding() -> Element` with a private fixed five-entry `Page` array (`image` stem plus title/body Fluent keys), page-index signal, and visibility signal initially false for SSR/hydration agreement. In a post-hydration `use_effect`, follow the existing guarded `document::eval` pattern: show page 0 unless `localStorage.getItem("bk-onboarding-complete-v1") == "true"`; on storage-read failure, show it. `complete()` must attempt `setItem(..., "true")`, ignore storage exceptions, and close immediately; a failed write therefore permits the guide to return on the next load.
   - Use `dioxus_primitives::dialog::{DialogRoot, DialogContent, DialogTitle, DialogDescription}` directly, not the destructive `AlertDialog`. Keep `DialogRoot` controlled and ignore primitive outside/Escape close requests so the introduction cannot disappear accidentally; only the visible Skip button or final Get started button calls `complete()`. Let the primitive provide accessible labelling, modal focus trapping, and focus restoration.
   - Render the locale-specific image URL `/static/onboarding/{locale.code()}/{page.image}.png`, page title/body, numeric counter and five noninteractive dots, Skip on every page, Back only after page 1, Next through page 4, and Get started on page 5. Back/Next change only the bounded page index and never write storage.
   - Add an `assets/app.css` onboarding section using existing color/radius/shadow/font tokens: fixed backdrop and card at z-index 4000 (above navbar 1100, tap shield 2000, and photo viewer 3000), subtle primitive open/close fade/scale, reserved `8 / 5` image area, card max width about 56rem, internal vertical overflow, and safe-area-aware padding. At `max-width: 700px`, use the available width/`100dvh`, cap the image height, wrap controls without hiding Skip/Back/Next, and suppress motion under `prefers-reduced-motion`.

## Critical files & anchors
- `service.py` — PEP 723 dependency header, existing `load_env`/Click command split, app-health conventions, and the new host-side browser capture pipeline.
- `src/components/onboarding.rs` — new fixed five-page state machine, dialog semantics, locale-aware image lookup, and localStorage contract.
- `src/components/shell.rs::MapShell` — persistent public-route mount and existing guarded localStorage precedent.
- `src/components/datenschutz.rs::Datenschutz` — explicit storage inventory where the new key must appear.
- `scripts/demo_store.sql` — deterministic default screenshot fixture name/content/coordinates; its database ID is deliberately not stable, and `--store-name` may select another public store.

## Verification
1. From the repository root, with `.env`, the app, a public store with at least one product, and pinned Chromium available, run `./service.py screenshots --store-name "Obstgarten Maier"`. Expected: exit 0 and ten named 1280×800 PNGs under `public/static/onboarding/{de,en}/`, all based on that exact selected store. Open all ten and confirm each shows the specified live route/state, nonblank OSM tiles, correct locale, and no onboarding overlay or credential. Record their hashes, run `./service.py screenshots --base-url http://127.0.0.1:1 --store-name "Obstgarten Maier"` (expected nonzero), and verify the hashes are unchanged.
2. Run `cargo test --no-default-features --features server` and `cargo check --no-default-features --features web`; then run `./service.py screenshots --help` and confirm `--base-url` plus `--store-name` with default `Obstgarten Maier` are listed.
3. Rebuild/start the stack with `./service.py up` so generated static assets and frontend changes are bundled. In a 1280×800 browser context, remove `bk-onboarding-complete-v1` and load `/`: the modal appears after hydration at `1 / 5`; each Next/Back boundary shows the exact ordered localized page and matching image; Back is absent on page 1; page 5 says Get started. Tab/Shift-Tab stay inside the dialog, and backdrop click/Escape do not dismiss it.
4. Click Skip on an intermediate page: the modal closes and localStorage becomes exactly `"true"`; reload and route changes do not reopen it. Repeat from a cleared key and finish page 5 with Get started for the same result. Set the key to any non-`"true"` value and reload: the modal appears. With `Storage.getItem`/`setItem` forced to throw, it still appears and closes for the current load without crashing.
5. Switch to English, clear the key, and repeat the five pages: English copy and `/static/onboarding/en/...` images appear. At 390×844, verify the screenshot, body, step indicator, Skip, and navigation controls remain visible/reachable without page-background interaction or horizontal overflow.
6. Visit `/datenschutz` in both locales and verify the rendered storage list names `bk-onboarding-complete-v1` and retention. Log in and visit `/admin`; the onboarding is absent there because it is mounted only in `MapShell`.

No permanent browser test is added: the repository has no E2E harness, and storage/dialog/static-asset behavior is proven against the actual application rather than by testing source wiring.

## Assumptions & contingencies
- Generate ten locale-matched desktop screenshots, not five German-only images or separate mobile variants. This avoids English instructions around German controls while one fixed `8 / 5` source size scales cleanly in the responsive modal.
- Dismissing the versioned guide is browser-local and permanent until site data is cleared. There is no account sync or reopen control because neither was requested; a future materially changed guide can use a new versioned key.
- Screenshot regeneration requires the running app, external OSM tiles, and the exact public store selected by `--store-name`, which must expose at least one product. The default is the existing demo-seeded `Obstgarten Maier`; a custom name removes that demo-fixture requirement. The command fails rather than silently creating data or accepting a blank map; OSM may change tile pixels even with all application/browser state fixed.
